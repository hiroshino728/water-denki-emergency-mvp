# ADR-001: プラットフォーム本体にBubbleを採用する

## 採用日
2026-08-02

## 背景
一人・非エンジニア・月数万円の予算で、フェーズ1(マッチングプラットフォームのMVP)を最速で市場検証する必要がある。将来的にはAI電話・AI受付・AI営業・AIエージェント群を含む「AI企業」への拡張を視野に入れている。

## 選択肢
- **Bubble**(ノーコード、Web中心)
- **FlutterFlow**(ノーコード、ネイティブモバイル中心)
- **Next.js + Supabase等によるAI駆動開発**(フルスクラッチに近い)

## 採用
Bubble

## 理由
- 非エンジニアでもDB・ワークフロー・画面を1つのツール内で完結でき、市場検証速度を最優先できる
- Data API / Workflow APIが標準搭載されており、将来的にn8n等の外部自動化ツールやAIエージェントから読み書きする拡張が可能
- 月額$29(Starterプラン)からと、当初予算の制約内に収まる

## 見直し条件
以下のいずれかに該当した場合、本ADRを見直す。

- 加盟店(職人)側で、プッシュ通知・GPS取得の精度不足による案件見逃しが実際に問題として顕在化した場合 → 加盟店向けのみFlutterFlowでのネイティブアプリ化を検討
- Bubbleのワークフロー5分タイムアウト制限、またはワークロードユニット(WU)費用の高騰が実際にボトルネックになった場合 → 該当機能のみ外部バックエンド(Supabase等)へ切り出し
- 加盟店数100社、または月間案件500件を超えた場合 → アーキテクチャ全体を再評価

## 設計上の注意点(関連ADR/ドキュメント)
- データモデルは `data_model_phase1.md` の通り、Bubble内部IDに依存せず業務ID(job_no等)を持たせることで、将来の移行コストを下げる設計としている
- 業務ロジック・AIの中核はBubble内に固めすぎず、必要に応じてBubbleの外(n8n等)に出す方針とする
