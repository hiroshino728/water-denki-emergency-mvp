# Business Workflow(業務フロー) - Phase1

このドキュメントは、Bubbleの画面・Workflowを作る前に「誰が・いつ・何を判断するのか」を固めるためのものです。`data_model_phase1.md` の `Job.status` `JobStatusLog` `InquiryLog` は、ここで定義する流れをデータとして記録するために設計されている。

---

## 1. 顧客フロー(メインフロー)

```
① 問い合わせ
   顧客がWeb/LINEでトラブル内容(カテゴリ・住所・緊急度)を入力
   → InquiryLog に記録
        ↓
② 受付・案件化
   運営(あなた)またはAIが内容を確認し、Jobを作成(status: new)
   → InquiryLog.resulted_job_id をJobに紐付け
        ↓
③ 加盟店検索・通知(自動・同時通知)
   category_id × region_id に合致するPartnerをPartnerSkillから検索
   → 該当する加盟店全員へLINEで自動一斉通知(同時送信)
   ※電話は現時点では使用しない(将来AI電話導入時に追加検討。vision.md「Not Now」参照)
        ↓
④ 受注確定
   最初に「対応可能」と回答した加盟店1社で自動確定 → Job.status: matched、Job.partner_id を確定
   ※複数社が同時に応答した場合は先着1社を正とし、他の加盟店には自動で辞退連絡(LINE)を送信する
   (辞退された場合は 5. 例外フロー「辞退」へ)
        ↓
⑤ 訪問・作業
   加盟店が現地訪問・作業実施 → Job.status: in_progress
        ↓
⑥ 完了報告
   加盟店から作業完了報告 → Job.status: completed、final_amount / gross_profit を記録
        ↓
⑦ 請求
   Invoice発行(status: issued) → 顧客が支払い → Payment(status: succeeded)
        ↓
⑧ レビュー
   顧客がReview(rating, comment)を登録
```

### 判断ポイント(誰が・何を)

| ステップ | 判断者 | 判断内容 |
|---|---|---|
| ②受付・案件化 | 運営(将来はAI受付) | 緊急度の判定、対応可否の一次判断 |
| ③加盟店検索・通知 | システム(自動) | 該当加盟店全員へLINE一斉送信(判断不要・機械的に実行) |
| ④受注確定 | 加盟店/システム | 対応可否の回答(加盟店)。先着判定・自動確定処理(システム) |
| ⑥完了報告 | 加盟店→運営 | 完了の事実確認、金額の確定 |

## 2. 加盟店フロー

```
① 加盟店登録申請
   Web経由で申請 → Partner(screening_status: pending)
        ↓
② 審査
   運営が資格・保険情報を確認 → approved / rejected
        ↓
③ 対応可能カテゴリ・地域の登録
   PartnerSkill に登録
        ↓
④ 案件通知の受信
   LINEで案件通知を自動受信(同時送信・先着順)※電話は現時点では使用しない
        ↓
⑤ 対応可否の回答
   受注する/辞退する
        ↓
⑥ 訪問・作業・完了報告
        ↓
⑦ 加盟店への支払い(Partner Payout)
   ※ 現時点のデータモデルに未定義。Invoice/Paymentとは別に、
     「運営→加盟店」への支払いフローを別途定義する必要がある(要追加検討)
```

---

## 3. 運営フロー(あなた自身の日次オペレーション)

```
① 問い合わせ監視
   InquiryLog / Web管理画面を確認(通知が来たら即対応)
        ↓
② 案件化・加盟店への取り次ぎ
   手動で加盟店に連絡(電話/LINE)
        ↓
③ 進捗確認
   JobStatusLog を見ながら、滞留している案件がないか確認
        ↓
④ 請求・入金確認
   Invoice/Paymentの状態を確認、未入金があればフォロー
        ↓
⑤ レビュー・クレーム対応
   低評価・クレームがあれば個別に対応
```

## 4. 例外フロー

### 4.1 加盟店の辞退

```
加盟店が受注を辞退
   ↓
Job.status は matched に進まず new のまま
   ↓
JobStatusLog に「辞退」を記録(changed_by: partner)
   ↓
次の候補加盟店へ通知(③加盟店検索に戻る)
```

### 4.2 再割当(訪問後のキャンセル・対応不可)

```
加盟店が訪問したが対応不可と判明(部材不足・専門外等)
   ↓
Job.status: in_progress → new に差し戻し
   ↓
JobStatusLog に理由を記録
   ↓
別の加盟店へ再割当
```

### 4.3 顧客都合のキャンセル

```
顧客が依頼をキャンセル
   ↓
Job.status: cancelled
   ↓
キャンセルのタイミングによっては加盟店へのキャンセル料発生ルールを検討(要追加検討)
```

### 4.4 クレーム・低評価

```
Review.rating が低い、またはクレームが入る
   ↓
運営が個別対応(返金・再訪問手配等)
   ↓
Partner.screening_status の見直し判断(繰り返す場合は契約見直し)
```
